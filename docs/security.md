# Security design and outstanding controls

Passwords use Argon2id. Access JWTs expire after ten minutes, are held only in client memory, and are checked against a live session. Refresh tokens are random 256-bit values, stored as SHA-256 hashes server-side and rotated after use. Replay revokes the token family. Sessions expire after seven days and after 30 minutes of server-observed inactivity. Production cookies use HttpOnly (refresh), Secure and SameSite=Strict. Refresh/logout require the configured exact Origin and a per-session CSRF token. API business routes require a Bearer token, not refresh cookies.

Invitation/password reset tokens are one-use, one-hour, hashed records. Password updates revoke sessions. Email provider delivery is not implemented; forgot-password intentionally returns a neutral message. Authorized company administrators can issue a reset token through the user-access screen for secure manual delivery. Invitation/reset responses are no-store. Never put them in logs. A delivery adapter and complete account activity auditing are release requirements.

Rate limits currently use process memory; scaling beyond one instance requires a shared store. Login rate limiting is per IP, with generic credential failures. A dummy Argon2 hash is verified for unknown accounts. TOTP setup requires the current password, enrollment cannot replace enabled MFA, and one login code per time step is consumed atomically. Enrollment UI is implemented. Account-aware stuffing mitigation, recovery codes, administrator MFA enforcement, abuse monitoring and broad timing analysis remain outstanding.

Sensitive government IDs and bank information are encrypted together with AES-256-GCM, fresh 96-bit nonce per write and a 32-byte secret key. Encryption fields are excluded from ordinary queries. Only masked bank last-four appears in profiles. Restricted payment export decrypts authorized bank records. Keys must be held in an environment secret manager; key versioning/rotation remains outstanding. Restrict salary, export and payslip access with company and employee scope.

Helmet, strict environment validation, input Zod schemas, bounded JSON payloads, safe errors, generated correlation IDs and no-store API responses are enabled. No credentials or identifiers are intentionally logged. Production requires HTTPS origin and a correctly configured trusted reverse proxy. Audit records cover principal business changes, known-account successful/failed logins, logout and refresh replay; coverage is not yet exhaustive. Application-level append-only audit routes are not database-level tamper resistance.

Release gates: independent security review, field-key rotation, least-privilege Atlas identity, private networking, exact CORS allowlist, broader transaction/race tests, documentation exposure review, audit retention/monitoring, encrypted backups/restore drill and privacy review. Dependency audit and basic cache/account isolation checks pass in this increment. Company-specific lawful processing, retention, erasure and employment-record obligations require professional review; no legal retention period is invented here.
